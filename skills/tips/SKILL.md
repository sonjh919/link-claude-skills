# Tips: Claude Code 활용도 분석

사용자가 방금 마친 작업을 돌아보고, 더 효율적으로 할 수 있었던 Claude Code 기능을 제안한다.

## 분석 절차

### 1단계: 현재 대화 분석

현재 대화에서 다음을 파악한다:

- **수행한 작업**: 무엇을 했는가 (코드 작성, 버그 수정, 탐색, 리팩토링 등)
- **사용한 도구**: 어떤 도구를 썼는가 (Read, Edit, Bash, Grep, Agent 등)
- **작업 패턴**: 반복된 패턴이 있는가 (같은 명령 반복 승인, 순차적 탐색, 수동 복사 등)
- **대화 길이**: 컨텍스트가 얼마나 소비되었는가
- **외부 도구 사용**: CLI 도구, MCP, 이미지 등 활용 여부

### 2단계: 기능 레퍼런스 대조

`references/features.md`를 읽고 각 기능의 **감지 기준**과 현재 대화의 패턴을 대조한다.

감지 기준에 부합하는 기능만 제안한다. 모든 기능을 나열하지 않는다.

### 3단계: 제안 선별

다음 기준으로 제안을 필터링한다:

- **관련성**: 이 작업에서 실제로 도움이 되었을 기능만
- **실현 가능성**: 사용자의 환경에서 바로 적용 가능한 것 우선
- **영향력**: 시간 절약이나 품질 향상 효과가 큰 순서로

제안은 **최대 5개**로 제한한다. 핵심적인 것만 전달하는 것이 효과적이다.

### 4단계: 마크다운 파일 생성

현재 작업 디렉토리에 `tips-YYYY-MM-DD.md` 파일을 생성한다.
같은 날짜의 파일이 이미 있으면 `tips-YYYY-MM-DD-2.md`처럼 번호를 붙인다.

파일 형식:

```markdown
# Claude Code 활용 팁

> 생성일: YYYY-MM-DD

## 작업 요약
이번 세션에서 수행한 작업을 2-3문장으로 요약.

## 활용한 기능
- **기능명**: 어떻게 활용했는지 간단히

## 개선 제안

### 1. 제안 제목
- **기능**: 기능명
- **이 작업에서**: 구체적으로 어떤 상황에서 이 기능을 쓸 수 있었는지
- **사용법**: 실제 명령어나 사용 방법
- **공식 문서**: URL

### 2. 제안 제목
...

## 다음에 시도해볼 팁
가장 쉽게 바로 적용할 수 있는 한 가지를 구체적으로 제안.
```

### 5단계: 텍스트 응답

파일 생성 후 간단한 텍스트 요약을 출력한다:

- 핵심 제안 1-2개를 한 줄씩
- 생성된 파일 경로

장황하게 설명하지 않는다. 자세한 내용은 파일에 있다.

## 주의사항

- 사용자가 이미 잘 활용하고 있는 기능은 칭찬하되 짧게만 — 핵심은 개선 제안이다.
- "~해야 합니다" 같은 지시적 톤이 아니라, "~하면 더 빠르게 할 수 있어요" 같은 제안 톤을 사용한다.
- 현재 작업과 전혀 무관한 기능은 제안하지 않는다.
- git log나 외부 이력을 참고할 수 있다면 활용하되, 현재 대화 분석이 핵심이다.
